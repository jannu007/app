# どうぶつ言の葉 - 犬・猫の気持ちがわかる無料アプリ

犬や猫の鳴き声を録音すると、**声の高さ・長さ・回数・テンポ・語尾の上がり下がり・音色・ゴロゴロ音のリズム**を端末内で解析し、動物行動学の研究で知られている傾向と「いまの状況」から気持ちを推定して「ことば」にします。しっぽ・耳・目などの**しぐさ**からの気持ち診断と、結果の**記録**もできます。

> 動物の「ことば」を正確に翻訳できる技術は、まだ世界に存在しません。結果は「こんな気持ちかも」という推定です。体調が心配なときは獣医師に相談してください。

| 開発 | VS Code / Node.js / TypeScript / esbuild / Zod（すべてOSS） | 0円 |
| 公開 | GitHub Pages（このリポジトリの既存ワークフロー） | 0円・カード登録不要 |

サーバーもデータベースも持たないため、無料枠の休止（Supabase の非アクティブ停止など）や従量課金の心配がありません。データベースが無いので、SQLインジェクションや他人のデータを覗けてしまう不備（IDOR）も原理的に起きません。

## 主な機能

- **鳴き声**：マイクで最大6秒録音、または録音済みの音声・動画ファイルから解析（15秒まで）
  - 犬：警告（うなり）／警戒・お知らせ／要求／遊ぼう／寂しい・不安／痛い・びっくり／遠吠え
  - 猫：要求／あいさつ／不満／威嚇（シャー）／安心（ゴロゴロ）／発情・縄張り／狩りモード（クラッキング）／警告（ウーッ）
  - 状況（ごはん前・来客・ひとりの時・遊び中・なでている時・病院・夜）で重みづけ
  - 興奮度メーター、ほかの可能性、判定のよりどころ、飼い主ができることを表示
- **しぐさ**：犬24種・猫26種のサインから気持ちを推定。うれしいサインと緊張のサインが混ざると注意を表示
- **記録**：結果とメモを端末内に保存
- オフライン対応・ホーム画面にインストール可能（PWA）

## 判定のしくみ（`src/analyzer.ts` / `src/interpret.ts`）

1. 音声を16kHzに変換し、64msごとに音量・基本周波数（YIN法）・スペクトル平坦度（ザラザラ感）・スペクトル重心（明るさ）を計算
2. 鳴いている区間を切り出し、回数・長さ・テンポ・語尾の音程変化を求める。ゴロゴロ音は振幅の20〜60Hzの周期的なうねりで検出
3. 以下の知見をもとにしたファジィルールで各候補の当てはまりを計算し、状況で重みづけ
   - Morton (1977)：低く濁った声は威嚇、高く澄んだ声は不安・なだめ
   - Pongrácz ほか (2005)：見知らぬ人への吠えは低く・ザラつき・間隔が短い／ひとりの時は高く・澄んで・間隔が長い
   - Schötz ほか：猫の要求のニャーは語尾が上がり、ストレス場面では下がりやすい
   - Briefer (2012)、Filippi ほか (2017)：声が高く・大きく・速いほど興奮度が高い

## セキュリティ

- **音声は端末の外に出ない**：録音データは解析後すぐ破棄。保存するのは結果の文字だけ
- **Content-Security-Policy**：自サイトのスクリプトのみ実行可（インラインスクリプト・外部スクリプト・`eval` 不可）、`object-src 'none'`、`base-uri 'none'`、`form-action 'none'`
- **XSS対策**：画面への表示はすべて `textContent`（`innerHTML` 不使用）
- **入力検証（Zod）**：名前・メモ（長さ・制御文字）、音声ファイル（種類・30MB上限）、localStorage の読み込み（1件ずつ検証し、壊れた・改ざんされた項目は捨てる）
- **TypeScript strict**（`noUncheckedIndexedAccess`・`exactOptionalPropertyTypes` など）、`any` 不使用
- 秘密情報（APIキー等）は一切使わないため `.env` も不要
- 依存は Zod のみ（実行時）。バージョンを固定し、`npm audit` で既知の脆弱性 0 件を確認

## 開発

```
cd kotonoha
npm ci
npm run check     # 型チェック + テスト + ビルド（js/ に出力）
```

`src/*.ts` を編集したら `npm run build` で `js/app.js` を作り直してコミットしてください（GitHub Pages はビルドなしでそのまま配信するため）。CI（`.github/workflows/kotonoha-check.yml`）が、型・テスト・ビルド結果のコミット漏れをチェックします。

試すとき（マイクは HTTPS か localhost のみで動作）：

```
# リポジトリのルートで
python3 -m http.server 8000
# → http://localhost:8000/kotonoha/
```

## 公開

`main` ブランチに入れば、既存の GitHub Pages ワークフローで `/kotonoha/` に自動公開されます。

公開前チェック：
- [ ] `npm run check` が通る／`npm audit` が 0 件
- [ ] HTTPS で開き、マイク許可ダイアログ → 録音 → 結果表示まで動く
- [ ] DevTools の Console に CSP 違反が出ていない
- [ ] ネットワークタブで、録音後に音声データの送信が無いこと

## ファイル構成

- `index.html` / `css/style.css` - 画面
- `src/` - TypeScript のソース（`analyzer.ts` 音響解析、`interpret.ts` 鳴き声の判定、`body.ts` しぐさ、`schemas.ts` Zodスキーマ、`storage.ts` 端末内保存、`audio.ts` 録音、`main.ts` 画面制御）
- `js/` - ビルド済みファイル（`npm run build` で生成）
- `test/` - テスト（合成した鳴き声で判定を確認）
- `manifest.webmanifest` / `sw.js` / `icons/` - PWA
- `scripts/build.mjs`・`scripts/make_icons.py` - ビルド・アイコン生成
